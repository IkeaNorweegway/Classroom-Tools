# Tests & Quizzes
*Formative checks and summative assessments — outcome-mapped*

**Pedagogical framework:** `_meta-context.md` governs how to think and design. This file governs structure and format. Read both.

## ⛔ Pre-Build Gate — confirm all four before writing question 1

| # | Constraint | What failure looks like |
|---|---|---|
| 1 | **Outcome map first** — list every LO being assessed, then write items; never reverse-engineer | Items written first, LO assigned after; an LO from the unit not covered by any item |
| 2 | **Every item maps to exactly one specific LO** — if you can't state which LO an item assesses, cut the item | A "general knowledge" item; a trick question; a question testing something not in the LOs |
| 3 | **No surprises** — students who studied the learning outcomes know what the test covers | Novel scenarios that require knowledge outside the LOs; trick wording; items on out-of-scope content |
| 4 | **Rubric or mark scheme for every extended response item** — included in the answer key before finalising | Extended response item with no rubric; rubric written after the fact |

State this before writing: *"Outcome map complete. LOs covered: [list LO codes]. Every item maps to a specific LO. Extended response rubric included."*

For quizzes, also confirm: "Quiz covers clusters [N]–[N] only (mid-unit scope). Full test covers all LOs."

Start from `templates/quiz-template.md` or `templates/test-template.md` — copy it, then fill in content.

## Purpose
Quizzes check understanding during a unit. Tests assess it at the end. Both must map every item to a specific learning outcome — if you can't say what outcome an item assesses, cut the item.

## Design principles
- **Map before you write.** List the outcomes first, then write items for each. Don't write questions and reverse-engineer the outcomes.
- **Vary the cognitive demand.** Not all recall. Include application, analysis, and at least one item requiring explanation.
- **Quizzes are low-stakes and frequent.** 5–10 minutes, 4–8 items, used to adjust teaching — not to sort students.
- **Tests should have no surprises.** If a student studied the outcomes, they should know what's coming. Surprise ≠ rigor.

## File naming
`[subject]-[unit]-[type]-[grade]-v[N].md`
Example: `science-cells-quiz-gr7-v1.md`
Types: `quiz` · `test` · `exit-ticket` · `question-bank`

## What to include in every assessment
1. **Header:** Subject, unit, type, grade, total marks, time allocation
2. **Outcome map:** A table showing which item assesses which outcome (can be teacher-facing only)
3. **Instructions:** Clear, one sentence per section
4. **Items:** With marks indicated per item
5. **Answer key / rubric:** Separate file or appended section, teacher-facing

## Question types to use
- **Selected response** (MC, T/F) — for recall and recognition; quick to mark
- **Short answer** — for application and explanation; 2–4 sentences expected
- **Extended response** — for analysis and synthesis; use a rubric, not a mark scheme
- **Exit ticket** — 1–2 questions, 3 minutes, informal; best formative tool available
