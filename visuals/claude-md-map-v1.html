BUILDThe build protocol, in order

A. Trust mode?Only when the user says "i trust you." Then: state "Trust mode active", skip per-step confirmation, and flag (never silently guess) any ambiguity that would need rework.
↓
B. Artifact compliance checkBefore the first line. Applies even in trust mode.
1. Copy the template from templates/
2. Read the artifact context file
3. State the gate constraint (see the gate cards below)
↓
C. Build the artifactFill the template. Keep it clean enough to print as-is.
↓
D. Evidence checkEmbeds at least one Tier 1 strategy AND passes 3 of 5 checklist items in templates/evidence-design-principles.md. Tier 1 units need all 5.
↓
E. Save with the naming ruleType folder, then subject, then unit. Never overwrite: bump -v[N]. Renders go only in public/materials/.

GATEGate constraint per artifact type

Step B3: say the matching line out loud before writing.

Workbook

Interleaving confirmed. No part headers.

Template: workbook. Clusters with ★/★★ levels and notes context.

Notes package

Progressive blanking confirmed.

Refutation-first on misconceptions. State section order and why.

Quiz

Outcome map complete.

Every item maps to a specific learning outcome (LO).

Unit test

Outcome map complete. All LOs covered.

Includes an extended response rubric.

Exit tickets

One ticket per cluster.

Every question maps to a specific LO.

Thinking prompt

Requires showing reasoning, not recalling.

No template.

Game

Outcomes, model, real-time or turn-based, test hook.

Full rules in _games-context.md. HTML only.

RULESTwo hard rules, always

1. Every test item maps to an LO

No orphan questions on quizzes or tests.

2. Every thinking prompt asks for reasoning

If the answer is a recalled fact, rewrite the prompt.

Also: the repo is public. Check any new test, or anything with names in it, against .gitignore before committing.
